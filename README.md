# Artham

**Offline fundamental research for Indian equities, with a language model that runs on your phone.**

Artham is an independent Android application built from scratch. It gives you the parts of a
fundamental screener that matter — a local database of company financials, a query language that
filters thousands of companies in milliseconds, ten-year financial statements, ratio analytics,
peer comparison and a deterministic strengths/concerns checklist — and it adds a local analyst:
answers are generated by a model running on the device, grounded only on numbers already stored
there. No API keys, no per-token billing, no data leaving the phone.

---

## Why it exists

Cloud screeners are excellent and they are somebody else's service: your queries, your watchlists
and your research trail live on their servers, and the analyst features they are adding bill per
token. Artham takes the opposite position. The database is a SQLite file in app-private storage,
the analytics are plain Kotlin running locally, and the language model is a file you supply that
runs on your own silicon.

## What it does

| Area | Detail |
|---|---|
| Dataset | Local SQLite store: companies, annual financials, quarterly financials, shareholding, quotes |
| Import | CSV and XLSX, read with a hand-written reader (no office-suite dependency) |
| Query language | `sales > 1000 AND roe > 15 AND debt_to_equity < 0.5`, with `BETWEEN`, `OR`, `NOT`, parentheses and arithmetic |
| Natural language | Sentence to query, via an offline phrase parser or the local model (validated before use) |
| Analytics | 47 metrics across market, size, growth, quality, leverage, efficiency, cash, valuation, scores and shareholding |
| Statements | Ten-year P&L, balance sheet and cash flow; quarterly results; shareholding pattern |
| Peers | Same-sector comparison on ROE, ROCE and P/E |
| Checklist | Deterministic strengths and concerns, every sentence traceable to a number |
| Analyst | On-device generation grounded on the stored figures, with the arithmetic shown |
| Screens | Save a query, re-run it, send every match to the watchlist |

## The two local engines

1. **On-device (MediaPipe / LiteRT)** — you import a `.task` or `.litertlm` bundle into app-private
   storage and the model runs inside the app process. Nothing is downloaded for you; model weights
   carry their own licence and the app will not accept it on your behalf.
2. **Local server (llama.cpp / Ollama / LM Studio / vLLM)** — point the app at `http://127.0.0.1:8080`
   or any machine on your own network. Both the Ollama protocol and the OpenAI-compatible protocol
   are detected automatically, and responses are streamed token by token.

The active engine is a setting. The analyst screen reports honestly when no model is configured
instead of failing silently.

## Data

Artham ships **no third-party financial data**. On first run it loads a small **synthetic** dataset
of twelve fictional companies so every screen is usable immediately; those companies are flagged and
carry a DEMO badge everywhere they appear. Real data arrives when you import a spreadsheet you
already own — for example a company or screen export from your own account with any provider, or a
file you maintain yourself.

Recognised import shapes:

* **Transposed company sheet** — metrics down the rows, periods across the columns (`Mar 2024`, `Mar-24`, `FY24`).
* **Long table** — one row per company-period, with a period column.
* **Wide snapshot** — one row per company, no period column; imported as a single period, with a warning naming the assumed year.

## Building

```bash
# JDK 17 and the Android SDK (platform 34, build-tools 34.0.0) are required
./gradlew assembleDebug        # -> app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease      # signed only when app/artham-release.jks is present
```

A CI workflow is included at `.github/workflows/build-apk.yml` and produces the debug APK as a
downloadable artifact on every push.

## Architecture

```
core/      formatting (Indian digit grouping), null-safe arithmetic, activity log
data/      SQLite schema, DAOs, settings, demo dataset, importers (CSV, XLSX, shape detection)
domain/    Financials view, ratio library, metric catalog, query lexer/parser/evaluator, templates, checklist
llm/       engine interface, MediaPipe engine, local-server engine, model packs, prompt builder, NL to query
ui/        Compose screens, design system, charts, navigation
```

No annotation processors: the database layer is hand-written SQL, which keeps the build fast and the
APK small, and makes every query readable in one file.

## Honest limitations

* Ratios are computed from what you import. A missing field produces a dash, never a zero.
* Shares outstanding come from the quote when available, otherwise from equity capital assuming a
  face value of ₹10 — stated wherever a per-share number depends on it.
* The Piotroski score substitutes two of the nine signals (no current ratio is stored); the
  substitution is documented in `Ratios.kt`.
* The DCF is a model with stated inputs, not a price target.
* Nothing here is investment advice.

### What is not verified

The app has not been executed on a physical device or emulator here. First-run behaviour,
Compose layout on real screens and model loading need hardware — see `KNOWN_ISSUES.md`.

### Building on a memory-constrained machine

If Gradle fails with `Could not reserve enough space` or a native malloc error, the shell
is capping address space. Raise it (`ulimit -v unlimited`) and give Gradle the memory it
needs; do not shrink the build. If dependency resolution fails with `UnknownHostException`
while `curl` works, an HTTP proxy is configured through environment variables and the JVM
is ignoring it — pass `-Dhttps.proxyHost` / `-Dhttps.proxyPort` to Gradle.

## Version 2.0 — what was added, and why

The second wave closes the gaps the research found in the market rather than the gaps
in my own backlog. `STRATEGY.md` has the reasoning and the sources; this is the summary.

**Point-in-time backtesting.** Screener has no backtesting at all and Trendlyne sells
200–1,200 backtests a year as a paid tier, so this is the largest unfilled demand in the
category. Artham replays a screen year by year, truncating each company to the periods
that existed at the time and **removing the current quote**, so a price-based metric
returns unknown rather than leaking today's price into 2019. It reports two separate
things: what happened to the businesses selected, and — only if you have imported price
history — what the share price did.

**Reverse DCF and sensitivity.** Rather than asking what a company is worth, the app now
asks what growth the current price already implies, which is a claim you can disagree
with. A 5×5 sensitivity grid over discount rate and growth sits beside it, because a
single DCF number without one is misleading.

**Portfolio with FIFO cost basis and XIRR.** Buy, sell, dividend, bonus and split
transactions replay into positions using first-in-first-out, the convention Indian tax
rules use for delivery trades. XIRR is solved by bisection rather than Newton-Raphson,
because Newton diverges on the irregular sign-changing streams a real ledger produces and
a wrong XIRR is worse than an honest null.

**On-device document intelligence.** Import the text of an annual report or a concall
transcript; the app chunks it, indexes it with BM25 and lets the local model answer from
the retrieved passages with citations. Retrieval is lexical, not semantic — deliberately,
because a vector index needs a second model file and BM25 can show you exactly which terms
matched.

**Alerts, comparison and export.** Saved screens re-evaluated on demand with a count
delta, four-way company comparison on twenty metrics, and CSV export of screen results,
statements and holdings through a FileProvider.

**Navigation rebuilt around it.** Home, Screen, Portfolio, Analyst, More. The tools that
do not need a tab live behind More, which keeps the bottom bar at five.

## Version 3.0 — live data and charts

The gap that mattered was data. Versions 1 and 2 could analyse whatever you imported; they
could not tell you anything about a company you had not already got a file for. That is now
fixed, and the app behaves like the product it was measured against.

**Two taps to a working app.** *Sync company list* downloads the exchange's published equity
master — 2,615 companies with ISIN and face value. *Sync top 65* then pulls five years of
daily prices and reported annual and quarterly fundamentals for the largest names. Each
company is committed as it arrives, so the sync is resumable and can be stopped.

**Real charts.** A candlestick chart with a volume strip, 50 and 200-day moving averages and
a 1M/3M/1Y/3Y/5Y range selector, drawn on the platform Canvas rather than a charting
dependency. Beside it, a P/E band against trailing reported EPS with the median and the
20th/80th percentile drawn as reference lines — reading a multiple against its own history is
the cheapest defence against paying a peak price for a peak multiple.

**Backtesting now uses real prices.** The price-history table that v2 left without an
importer is filled by the sync, so a backtest can report an equal-weight return and a hit
rate instead of only describing the businesses.

**Face value replaces an assumption.** Share count was previously derived by assuming a ₹10
face value. The exchange master file supplies the real one, and a test caught a latent bug in
that path that had been silently wrong by a factor of ten million whenever a quote lacked a
market cap — corrupting book value, the Graham number and the DCF.

`DATA_SOURCES.md` documents every endpoint, every field mapping, both derived fields, the
rate limits and the legal position. Read it before you rely on a number.

## Version 4.0 — the audit wave

An audit ran before anything was added, and it found things that mattered. The worst was in
the portfolio: a holding with no quote was valued at `EPS × 15`, an invented multiple,
reported as market value. A made-up number inside a profit figure is the one bug class this
project refuses to ship. It is now null, the holding is visibly marked unpriced, and it is
excluded from totals rather than estimated.

Three dead code paths were removed, peer rows on the company page now actually open the peer,
sync failures are shown instead of being written to a table nobody reads, snapshot imports
take the year from you rather than assuming one, and price history can be imported from a CSV.

Then 72 new capabilities, listed in `FEATURES.md` with a module for each. The ones that
change how the app is used:

**79 screenable metrics**, up from 47. The unusual part is that technical indicators are in
the same vocabulary as fundamentals, so `rsi14 < 35 AND roe > 15` is a valid screen. That
works because the price series is loaded alongside the financials when a screen runs.

**27 ready-made screens**, up from 12 — momentum, oversold quality, MACD crossovers, low
volatility, ROIC, distress watch, fortress balance sheets, cash yield, PEG, rising dividends,
asset-light compounders and more. Every query is compiled in a test, so a template can never
reference a metric that does not exist.

**A technical tab**: RSI, MACD, Bollinger, ATR, momentum, volatility, distance from the 200
DMA and volume spike, with RSI history and a MACD histogram.

**Eleven calculators** — SIP, step-up SIP, goal planning, lumpsum, withdrawal depletion,
capital gains tax, position sizing from a fixed risk, break-even, CAGR conversion and a
retirement corpus.

**Portfolio analytics**: Herfindahl concentration with an effective-holding count,
contribution to profit, dividend yield on cost.

**A glossary generated from the metric catalogue**, so it can never drift out of date.

`TOOLCHAIN.md` now lists every version, why it was chosen, what was deliberately left out,
and the five environment failures this project has actually hit — each of which looks like a
code error and is not.
