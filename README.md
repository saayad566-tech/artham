# Artham

**Offline fundamental research for Indian equities, with a language model that runs on your phone.**

Artham is an independent Android application built from scratch. It gives you the parts of a
fundamental screener that matter — a local database of company financials, a query language that
filters thousands of companies in milliseconds, ten-year financial statements, ratio analytics,
peer comparison and a deterministic strengths/concerns checklist — and it adds a local analyst:
answers are generated by a model running on the device, grounded only on numbers already stored
there. No API keys, no per-token billing, no data leaving the phone.

---

## Why it exists

Cloud screeners are excellent and they are somebody else's service: your queries, your watchlists
and your research trail live on their servers, and the analyst features they are adding bill per
token. Artham takes the opposite position. The database is a SQLite file in app-private storage,
the analytics are plain Kotlin running locally, and the language model is a file you supply that
runs on your own silicon.

## What it does

| Area | Detail |
|---|---|
| Dataset | Local SQLite store: companies, annual financials, quarterly financials, shareholding, quotes |
| Import | CSV and XLSX, read with a hand-written reader (no office-suite dependency) |
| Query language | `sales > 1000 AND roe > 15 AND debt_to_equity < 0.5`, with `BETWEEN`, `OR`, `NOT`, parentheses and arithmetic |
| Natural language | Sentence to query, via an offline phrase parser or the local model (validated before use) |
| Analytics | 47 metrics across market, size, growth, quality, leverage, efficiency, cash, valuation, scores and shareholding |
| Statements | Ten-year P&L, balance sheet and cash flow; quarterly results; shareholding pattern |
| Peers | Same-sector comparison on ROE, ROCE and P/E |
| Checklist | Deterministic strengths and concerns, every sentence traceable to a number |
| Analyst | On-device generation grounded on the stored figures, with the arithmetic shown |
| Screens | Save a query, re-run it, send every match to the watchlist |

## The two local engines

1. **On-device (MediaPipe / LiteRT)** — you import a `.task` or `.litertlm` bundle into app-private
   storage and the model runs inside the app process. Nothing is downloaded for you; model weights
   carry their own licence and the app will not accept it on your behalf.
2. **Local server (llama.cpp / Ollama / LM Studio / vLLM)** — point the app at `http://127.0.0.1:8080`
   or any machine on your own network. Both the Ollama protocol and the OpenAI-compatible protocol
   are detected automatically, and responses are streamed token by token.

The active engine is a setting. The analyst screen reports honestly when no model is configured
instead of failing silently.

## Data

Artham ships **no third-party financial data**. On first run it loads a small **synthetic** dataset
of twelve fictional companies so every screen is usable immediately; those companies are flagged and
carry a DEMO badge everywhere they appear. Real data arrives when you import a spreadsheet you
already own — for example a company or screen export from your own account with any provider, or a
file you maintain yourself.

Recognised import shapes:

* **Transposed company sheet** — metrics down the rows, periods across the columns (`Mar 2024`, `Mar-24`, `FY24`).
* **Long table** — one row per company-period, with a period column.
* **Wide snapshot** — one row per company, no period column; imported as a single period, with a warning naming the assumed year.

## Building

```bash
# JDK 17 and the Android SDK (platform 34, build-tools 34.0.0) are required
./gradlew assembleDebug        # -> app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease      # signed only when app/artham-release.jks is present
```

A CI workflow is included at `.github/workflows/build-apk.yml` and produces the debug APK as a
downloadable artifact on every push.

## Architecture

```
core/      formatting (Indian digit grouping), null-safe arithmetic, activity log
data/      SQLite schema, DAOs, settings, demo dataset, importers (CSV, XLSX, shape detection)
domain/    Financials view, ratio library, metric catalog, query lexer/parser/evaluator, templates, checklist
llm/       engine interface, MediaPipe engine, local-server engine, model packs, prompt builder, NL to query
ui/        Compose screens, design system, charts, navigation
```

No annotation processors: the database layer is hand-written SQL, which keeps the build fast and the
APK small, and makes every query readable in one file.

## Honest limitations

* Ratios are computed from what you import. A missing field produces a dash, never a zero.
* Shares outstanding come from the quote when available, otherwise from equity capital assuming a
  face value of ₹10 — stated wherever a per-share number depends on it.
* The Piotroski score substitutes two of the nine signals (no current ratio is stored); the
  substitution is documented in `Ratios.kt`.
* The DCF is a model with stated inputs, not a price target.
* Nothing here is investment advice.
